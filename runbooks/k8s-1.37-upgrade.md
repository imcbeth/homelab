# Kubernetes 1.36 → 1.37 Upgrade Plan

**Target:** v1.37.1 (latest patch, released 2026-09-15, EOL 2027-10-28)
**Current:** v1.36.3 across all 5 nodes
**Drafted:** 2026-10-24
**Owner:** operator (this runbook)

## TL;DR — do NOT start this yet

The kubeadm mechanics are routine and carry over from the 1.36 runbook. **The blocker is Istio.**

No released Istio version lists Kubernetes 1.37 as *supported*. Istio 1.30 (what we run, at 1.30.7) officially covers k8s 1.32–1.36. Even Istio 1.31 — the latest, released 2026-08-27 — places 1.37 in the "tested, but not supported" column. Our mesh runs **Ambient mode with mTLS cluster-wide**, so ztunnel and istio-cni sit directly in the data path of every pod. Running that combination outside the vendor's support matrix is a poor trade when nothing is forcing our hand.

**Nothing is forcing our hand:** 1.36 is supported until **2027-06-28**, eight months out.

Recommended sequencing instead:

| Phase | Action | Blocked on |
|---|---|---|
| **0** | Patch 1.36.3 → **1.36.5** | nothing — do this first, it is free |
| **1** | Calico **3.31.4 → 3.33.x** | nothing — required for 1.37 regardless |
| **2** | Wait for an Istio release that *supports* 1.37 (expect 1.32) | upstream |
| **3** | k8s 1.36.5 → **1.37.1** | Phases 0–2 |

Phases 0 and 1 are worth doing now; they are prerequisites either way and reduce the eventual change surface. Phase 3 should wait.

## What changed in 1.37 (pre-flight audit)

Sourced from the [1.37 CHANGELOG](https://github.com/kubernetes/kubernetes/blob/master/CHANGELOG/CHANGELOG-1.37.md) urgent-upgrade-notes. **Impact column is unverified** — the cluster was down when this was drafted; run the Pre-flight Checks section below before Phase 3.

### Action Required items (from the changelog)

| Change | Likely impact on us | Pre-flight check |
|---|---|---|
| **`scheduling.k8s.io` promoted v1alpha2 → v1alpha3, v1alpha2 dropped entirely.** Changelog: *"Remove all `v1alpha2` objects from the `kube-apiserver` before performing the cluster update."* | Probably none — we do not knowingly use alpha scheduling APIs | **Must verify.** Query below. |
| **`SELinuxMount` graduated to GA**, enabled by default; *"may break existing workloads in clusters with SELinux enabled"* | None expected — Ubuntu uses AppArmor, not SELinux | confirm SELinux absent |
| **`eventRecordQPS` now treats 0 as unlimited** (was: rate-limited) | Only if kubelet config sets it to 0 | grep kubelet config |
| **kubelet logs its effective config at startup**; advises restricting the `nodes/logs` ClusterRole | Config details become readable via node logs | RBAC review on `nodes/logs` |

### Removed metrics

cAdvisor stopped exporting `container_cpu_load_average_10s`, `container_cpu_load_d_average_10s`, and `container_tasks_state`, plus the custom `container_application_*` families. Audit PrometheusRules and Grafana dashboards before Phase 3.

### Other changes worth knowing

- **kube-proxy IPVS mode deprecated** (since 1.35); 1.37 adds a `KubeProxyIPVS` feature gate in preparation for deactivation (~1.40) and removal (~1.43). Non-blocking if we are on iptables — verify.
- **StatefulSets**: `MaxUnavailableStatefulSet` now enabled by default, and a new `Recreate` update strategy exists. Could change rolling behaviour of our 5 StatefulSets. Default `maxUnavailable` remains 1, so no change expected.
- **CSI**: `preventPodSchedulingIfMissing` added to CSIDriver; `VolumeLimitScaling` promoted to Beta. Relevant to synology-csi but opt-in.
- **Admission webhooks**: `ExcludeAdmissionWebhookVirtualResources` beta and on by default — excludes `tokenreviews`/`subjectaccessreviews` from webhooks. Gatekeeper does not validate those, so no impact expected.
- **Feature gates removed**: `GangScheduling`, `WorkloadAwarePreemption`, `AnyVolumeDataSource` (locked on since 1.33). If any appear in our kubelet or apiserver flags, the component will refuse to start.

### Claims deliberately EXCLUDED from this plan

Several widely-circulated blog posts list three "1.37 upgrade blockers" that **do not appear in the changelog**. Each was searched for explicitly and returned not-found:

- `PreventStaticPodAPIReferences` removal / "static pods can no longer reference Secrets or ConfigMaps"
- Removal of `ClusterTrustBundle` v1alpha1, `IPAddress` v1beta1, `ServiceCIDR` v1beta1, `VolumeAttributesClass` v1beta1
- "kubelet hard-fails on cgroup v1 **as a 1.37 change**" — the `failCgroupV1=true` default landed in **1.35**, and the SIG-release thread states plainly: *"Nothing changes in v1.37 for cgroup v1."* We are already on 1.36, so this is behind us.

Do not reintroduce these without a primary-source citation.

## Pre-flight Checks (run when the cluster is up, before Phase 3)

```bash
# 1. The one hard ACTION REQUIRED: any scheduling.k8s.io v1alpha2 objects?
kubectl api-resources --api-group scheduling.k8s.io
kubectl get --raw /apis/scheduling.k8s.io 2>/dev/null | python3 -m json.tool
# Expect: no v1alpha2 in the served versions, and no objects in it.

# 2. SELinux present on any node? (expect "not found" / Disabled on Ubuntu)
for ip in 10.0.10.214 10.0.10.235 10.0.10.211 10.0.10.244 10.0.10.220; do
  echo -n "  $ip: "
  ssh -i ~/.ssh/id_ed25519_k8s imcbeth@$ip "getenforce 2>&1 || echo 'SELinux not installed'"
done

# 3. kube-proxy mode (iptables = fine; ipvs = deprecation path)
kubectl get cm kube-proxy -n kube-system -o jsonpath='{.data.config\.conf}' | awk '/mode:/'

# 4. eventRecordQPS set to 0 anywhere?
for ip in 10.0.10.214 10.0.10.235 10.0.10.211 10.0.10.244 10.0.10.220; do
  echo -n "  $ip: "
  ssh -i ~/.ssh/id_ed25519_k8s imcbeth@$ip "sudo awk '/eventRecordQPS/' /var/lib/kubelet/config.yaml || echo 'unset (default)'"
done

# 5. Removed cAdvisor metrics referenced in rules or dashboards?
kubectl get prometheusrules -A -o json | python3 -c "
import json,sys
bad=['container_cpu_load_average_10s','container_cpu_load_d_average_10s','container_tasks_state','container_application_']
hits=0
for r in json.load(sys.stdin)['items']:
    for g in r['spec'].get('groups',[]):
        for rule in g.get('rules',[]):
            e=rule.get('expr','')
            for b in bad:
                if b in e:
                    print('  HIT:', r['metadata']['namespace']+'/'+r['metadata']['name'], rule.get('alert') or rule.get('record'), b); hits+=1
print('  total hits:', hits)"

# Same sweep across Grafana dashboard ConfigMaps
kubectl get cm -A -l grafana_dashboard -o json | python3 -c "
import json,sys
bad=['container_cpu_load_average_10s','container_cpu_load_d_average_10s','container_tasks_state','container_application_']
hits=0
for c in json.load(sys.stdin)['items']:
    blob=json.dumps(c.get('data',{}))
    for b in bad:
        if b in blob: print('  HIT:', c['metadata']['namespace']+'/'+c['metadata']['name'], b); hits+=1
print('  total hits:', hits)"

# 6. Removed feature gates referenced in kubelet/apiserver flags?
for ip in 10.0.10.214 10.0.10.235 10.0.10.211 10.0.10.244 10.0.10.220; do
  echo "  --- $ip ---"
  ssh -i ~/.ssh/id_ed25519_k8s imcbeth@$ip \
    "sudo awk '/featureGates|GangScheduling|WorkloadAwarePreemption|AnyVolumeDataSource/' /var/lib/kubelet/config.yaml || echo '    none'"
done
ssh -i ~/.ssh/id_ed25519_k8s imcbeth@10.0.10.214 \
  "sudo awk '/feature-gates/' /etc/kubernetes/manifests/kube-apiserver.yaml || echo '  none'"

# 7. nodes/logs RBAC — who can read node logs?
kubectl get clusterrole -o json | python3 -c "
import json,sys
for r in json.load(sys.stdin)['items']:
    for rule in r.get('rules') or []:
        if any('nodes/log' in x for x in (rule.get('resources') or [])):
            print('  ', r['metadata']['name'], rule.get('verbs'))"
```

## Phase 3 — Kubernetes 1.36.5 → 1.37.1

Mechanics are unchanged from the 1.36 runbook. Rolling, one node at a time, control-plane first.

```bash
CP=10.0.10.214
SSH="ssh -i ~/.ssh/id_ed25519_k8s -o StrictHostKeyChecking=no imcbeth@$CP"

# 1. Switch apt repo v1.36 -> v1.37  (REQUIRED: pkgs.k8s.io is per-minor.
#    Without this, apt only ever offers 1.36.x and the upgrade silently no-ops.)
$SSH "sudo sed -i 's|/v1.36/deb|/v1.37/deb|' /etc/apt/sources.list.d/kubernetes.list"
$SSH "sudo apt-get update"
$SSH "sudo apt-cache madison kubeadm | head -5"   # confirm 1.37.1-1.1 appears

# 2. kubeadm first (unhold, install, re-hold)
$SSH "sudo apt-mark unhold kubeadm && sudo apt-get install -y kubeadm=1.37.1-1.1 && sudo apt-mark hold kubeadm"
$SSH "kubeadm version -o short"

# 3. Dry run, then apply
$SSH "sudo kubeadm upgrade plan"
$SSH "sudo kubeadm upgrade apply v1.37.1 -y"

# 4. Drain, upgrade kubelet+kubectl, restart
kubectl drain control-plane --ignore-daemonsets --delete-emptydir-data
$SSH "sudo apt-mark unhold kubelet kubectl && sudo apt-get install -y kubelet=1.37.1-1.1 kubectl=1.37.1-1.1 && sudo apt-mark hold kubelet kubectl"
$SSH "sudo systemctl daemon-reload && sudo systemctl restart kubelet"
kubectl uncordon control-plane
```

Then per worker (`node01` .235, `node02` .211, `node03` .244, `node04` .220), one at a time:

```bash
NODE=node01; IP=10.0.10.235
SSH="ssh -i ~/.ssh/id_ed25519_k8s -o StrictHostKeyChecking=no imcbeth@$IP"

kubectl drain $NODE --ignore-daemonsets --delete-emptydir-data
$SSH "sudo sed -i 's|/v1.36/deb|/v1.37/deb|' /etc/apt/sources.list.d/kubernetes.list && sudo apt-get update"
$SSH "sudo apt-mark unhold kubeadm && sudo apt-get install -y kubeadm=1.37.1-1.1 && sudo apt-mark hold kubeadm"
$SSH "sudo kubeadm upgrade node"
$SSH "sudo apt-mark unhold kubelet kubectl && sudo apt-get install -y kubelet=1.37.1-1.1 kubectl=1.37.1-1.1 && sudo apt-mark hold kubelet kubectl"
$SSH "sudo systemctl daemon-reload && sudo systemctl restart kubelet"
kubectl uncordon $NODE
kubectl get nodes $NODE
```

**Delete the Gatekeeper PDB before the drain sequence** (`kubectl delete pdb -n gatekeeper-system --all`) — with `minAvailable: 1` and 2 replicas, the second drain always blocks. ArgoCD restores it.

**Wait window per node:** 5–10 min. Watch the 8 iSCSI PVCs — each drain detaches and reattaches them, historically the flakiest path.

### ⚠️ MANDATORY: re-check static pod customizations after ANY kubeadm upgrade

`kubeadm upgrade apply` **rewrites** `/etc/kubernetes/manifests/*.yaml` and silently discards local edits. These files are host-level, not in git — no ArgoCD diff, no alert.

The 1.36 upgrade reverted `--bind-address=0.0.0.0` → `127.0.0.1` on kube-controller-manager and kube-scheduler. Their Prometheus targets were down **38 days** before anyone noticed.

```bash
ssh -i ~/.ssh/id_ed25519_k8s imcbeth@10.0.10.214 \
  "sudo grep -H bind-address /etc/kubernetes/manifests/kube-controller-manager.yaml \
                             /etc/kubernetes/manifests/kube-scheduler.yaml"
# Expect --bind-address=0.0.0.0 on BOTH. If reverted, restore per the 1.36 runbook
# (backups in /root/k8s-manifest-backups/), then confirm both scrape targets recover.
```

Treat this as a required post-step, not a nice-to-have.

## Rollback plan

Minor upgrades are effectively one-way for the data plane, but a 1.36→1.37 bump is re-pinnable if caught early.

**Control-plane failure mid-flight:**

```bash
$SSH "sudo sed -i 's|/v1.37/deb|/v1.36/deb|' /etc/apt/sources.list.d/kubernetes.list && sudo apt-get update"
$SSH "sudo apt-mark unhold kubeadm kubelet kubectl"
$SSH "sudo apt-get install -y kubeadm=1.36.5-1.1 kubelet=1.36.5-1.1 kubectl=1.36.5-1.1"
$SSH "sudo apt-mark hold kubeadm kubelet kubectl"
```

If control-plane static pods refuse to start, restore etcd per `runbooks/argocd-pvc-protection.md`.

**Worker failure:** the node can sit drained on a 1.36 kubelet indefinitely (one minor behind is supported). Fix, retry, no data loss.

## Known risks specific to this cluster

1. **Istio ambient out of support matrix.** The reason this plan is staged. ztunnel and istio-cni are in every pod's data path; an incompatibility is a cluster-wide outage, not a degraded feature.
2. **PVC RO cascade during drain.** Each worker drain detaches its RWO iSCSI PVCs. `pvc-ro-remediator` auto-heals within ~4 min. If the same PVC goes read-only twice, cordon and reschedule manually.
3. **Loki PVC retention.** Fixed 2026-10-24 (`enableStatefulSetAutoDeletePVC: false`), but re-verify before any procedure that scales loki to 0: `kubectl get sts loki -n loki -o jsonpath='{.spec.persistentVolumeClaimRetentionPolicy}'` should be empty.
4. **Chaos-mesh Wednesday schedules.** Suspend for the window.
5. **Control-plane is N=1.** No HA. The apiserver is unavailable during its own upgrade.
6. **kubeadm-proposed CoreDNS/etcd bumps.** Accept them; they are versioned to the minor.
